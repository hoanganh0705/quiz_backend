# Persistence Flow

This document describes how data moves from the database to the wire and back: schema design, repository pattern, transaction management, and the row-to-DTO pipeline.

## Schema Organization

Database schemas live under `src/core/database/schema/<context>/`. Each bounded context owns its own subdirectory:

```
src/core/database/schema/
├── index.ts                    ← re-exports all schemas + relations
├── drizzle.constants.ts         ← DI tokens (DRIZZLE)
├── database.module.ts          ← NestJS module (Drizzle client + all repositories)
├── migrations/                 ← 0000_*.sql (generated by drizzle-kit)
├── auth/
│   ├── schema.ts              ← users, user_sessions, password_reset_tokens, password_history, oauth_accounts, auth_audit_logs
│   └── relations.ts
├── taxonomy/
│   ├── schema.ts              ← tags, tag_follows, categories, category_follows
│   └── relations.ts
├── quiz/
│   ├── schema.ts              ← quizzes, quiz_versions, quiz_questions, quiz_answer_options, quiz_tags, quiz_stats, ...
│   └── relations.ts
├── discussion/
│   ├── schema.ts              ← discussion_threads, discussion_comments, discussion_votes, discussion_reports, ...
│   └── relations.ts
├── outbox/
│   └── schema.ts              ← outbox_events (shared by all modules)
└── [other contexts]
```

## Data Flow Layers

```
PostgreSQL
    │
    │  Drizzle ORM (infrastructure/repositories/)
    ▼
Row (database row — snake_case)
    │
    │  Mapper (src/modules/<m>/mappers/)
    ▼
DTO (TypeScript object — camelCase, class)
    │
    │  Application Service (orchestration)
    ▼
Response DTO (class with @ApiProperty)
    │
    │  Presenter (src/modules/<m>/transport/presenters/)
    ▼
ApiResponseEnvelope { data, meta }
    │
    │  ResponseFormatInterceptor (normalizeTemporalFields)
    ▼
Wire JSON (ISO 8601 timestamps, camelCase)
```

## Repository Pattern

Each bounded context has a repository port interface and a Drizzle adapter.

### Port Interface

Defined in `src/modules/<m>/domain/ports/<m>-repository.port.ts`. Exported as a `Symbol` DI token. Uses **row types** (plain TypeScript interfaces with snake_case field names) — never Drizzle types.

```typescript
// src/modules/tag/domain/ports/tag-repository.port.ts
export interface TagRepositoryPort {
  findById(id: string): Promise<TagRow | null>;
  findBySlug(slug: string): Promise<TagRow | null>;
  create(data: CreateTagInput): Promise<TagRow>;
  softDelete(id: string): Promise<boolean>;
}
```

### Drizzle Adapter

Injected with `@Inject(DRIZZLE) private readonly db: DrizzleDB`. Implements the port interface. Returns row types.

```typescript
// src/modules/tag/infrastructure/repositories/tag.repository.ts
@Injectable()
export class TagRepository implements TagRepositoryPort {
  constructor(@Inject(DRIZZLE) private readonly db: DrizzleDB) {}

  async findBySlug(slug: string): Promise<TagRow | null> {
    const [row] = await this.db
      .select()
      .from(tags)
      .where(and(isNull(tags.deletedAt), eq(tags.slug, slug)))
      .limit(1);
    return row ?? null;
  }
}
```

### DI Registration

In the module's `providers` array:

```typescript
// src/modules/tag/tag.module.ts
{ provide: TAG_REPOSITORY_PORT, useClass: TagRepository }
```

The domain service injects via the port token, never the concrete class:

```typescript
// src/modules/tag/domain/tag.service.ts
constructor(
  @Inject(TAG_REPOSITORY_PORT)
  private readonly tagRepository: TagRepositoryPort,
) {}
```

## Soft Delete

Every user-facing table exposes a `deletedAt: timestamp('deleted_at', { withTimezone: true })` column.

| Rule | Detail |
|---|---|
| All reads filter | Every query includes `WHERE deleted_at IS NULL` |
| Partial unique indexes | `UNIQUE (slug) WHERE deleted_at IS NULL` — lets deleted rows release their slug for reuse |
| Restore | `UPDATE SET deleted_at = NULL WHERE id = $1` |
| Hard delete | Never in feature code; only in outbox/audit cleanup tooling |

Repository code that requires the deleted row uses `findByIdIncludingDeleted` (a dedicated port method) — ordinary reads always filter by `deletedAt IS NULL`.

## Identifier Strategy

All primary keys are UUID v7:

```sql
id UUID PRIMARY KEY DEFAULT uuidv7()
```

Application code generates via `generateUuidV7()` from `src/common/utils/id-generator.ts`:

```typescript
// src/modules/tag/infrastructure/repositories/tag.repository.ts
await this.db.insert(tags).values({ id: generateUuidV7(), ... });
```

The Drizzle schema uses `sql\`uuidv7()\`` as the default. The application layer never uses `crypto.randomUUID()`.

## Transaction Management

### @Transactional() Decorator

Controllers or application service methods carry `@Transactional()` to opt into a transactional scope:

```typescript
@Post(':id/versions')
@Transactional()
async createVersion(...) { … }
```

### TransactionalInterceptor + AsyncLocalStorage

`TransactionalInterceptor` is a global interceptor registered in `CommonModule`. It checks for `@Transactional()` metadata and wraps the handler in `TransactionalContext.run()`:

```typescript
// src/common/interceptors/transactional-context.ts
export class TransactionalContext {
  private readonly storage = new AsyncLocalStorage<Map<string, unknown>>();
  run<T>(callback: () => T): T {
    return this.storage.run(new Map(), callback);
  }
  setDbClient(tx: unknown): void { this.storage.getStore()!.set('db', tx); }
  getDbClient(): unknown { return this.storage.getStore()?.get('db'); }
}
```

### Repository Transaction Participation

The repository checks whether a transaction already exists in the async context before opening a new one:

```typescript
// Conceptual pattern (all transactional repositories follow this)
const existing = transactionalContext.getDbClient();
if (existing) {
  return await this.runInTransaction(existing, ...);
}
return await this.db.transaction(async (tx) => {
  transactionalContext.setDbClient(tx);
  return this.runOperation(tx, ...);
});
```

This pattern ensures a single transaction for the entire call chain.

## Constraint-to-Exception Mapping

The repository maps Postgres constraint errors to domain exceptions:

```typescript
// src/modules/tag/infrastructure/repositories/tag.repository.ts
if (e.code === '23505') {
  if (e.constraint?.includes('slug')) {
    throw new TagSlugConflictError(...);
  }
}
if (e.code === '23503') throw new TagNotFoundError(...);
```

| Postgres error code | Meaning | Typical domain error |
|---|---|---|
| `23505` | Unique violation | `*ConflictError`, `*SlugConflictError` |
| `23503` | Foreign key violation | `*NotFoundError` |
| `23514` | Check constraint violation | `*ValidationError` |
| `23502` | Not-null violation | `*ValidationError` |

## Indexing Strategy

Indexes are declared inline in the Drizzle schema factory:

```typescript
// src/core/database/schema/taxonomy/schema.ts
export const tags = pgTable('tags', (t) => ({
  id: uuid('id').primaryKey().default(sql`uuidv7()`),
  slug: t.text().notNull(),
  deletedAt: t.timestamp({ withTimezone: true }),
}), (t) => ({
  slugUniqueIdx: uniqueIndex('idx_tags_slug_unique')
    .on(t.slug)
    .where(sql`deleted_at IS NULL`),
  activeCreatedAtIdx: uniqueIndex('idx_tags_active_created_at')
    .on(t.createdAt)
    .where(sql`deleted_at IS NULL`),
}));
```

Indexes are never created outside the schema definition. Ad-hoc `CREATE INDEX` in migrations is acceptable only when the Drizzle generator cannot express the constraint.

## Temporal Normalization

Timestamps are stored as `timestamp with time zone` in UTC and normalized to ISO 8601 UTC with milliseconds on the wire:

```
DB: 2026-07-15 03:09:00.000+00:00
    ↓ normalizeTemporalFields() in ResponseFormatInterceptor
Wire: "2026-07-15T03:09:00.000Z"
```

The normalizer identifies temporal fields by suffix pattern (`time`, `timestamp`, `date`, `at`, `updated`) and converts any parseable value to the canonical ISO 8601 format.

## Schema Naming Conventions

| Convention | Example |
|---|---|
| Table name | `snake_case` plural (`tags`, `quiz_versions`) |
| Column name | `snake_case` (`created_at`, `published_version_id`) |
| Index name | `idx_<table>_<columns>` (`idx_tags_slug_unique`) |
| Constraint name | `<table>_<column>_<kind>` (`tags_slug_format`) |
| Foreign key | `<table>_<column>_fkey` (Drizzle-generated) |

## Column Type Conventions

| Data | Type | Notes |
|---|---|---|
| UUID primary key | `uuid` | Default `uuidv7()` |
| Timestamp | `timestamp({ withTimezone: true })` | Always UTC |
| Boolean | `boolean` | Not `integer` |
| JSONB | `jsonb` | For metadata, event payloads |
| Enum | `text` | Not native PostgreSQL enum (Drizzle limitation) |
